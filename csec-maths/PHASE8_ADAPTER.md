# Phase 8 — CSEC Mathematics on the shared evidence API

**Date:** 2026-07-31
**Status:** implemented
**Depends on:** CSEC Additional Mathematics build, Phases 1–7 (`../../CSEC Additional Maths/CSEC_Add_Maths_Redesign_2026-07-30/`)

## What the inventory found

The Phase 8 instruction was *"write a client adapter rather than forking the
backend."* That presumes this client already submits attempts in some shape
needing translation.

It does not. Before this change there were **zero** references to `/v1/`,
`fetch(`, `XMLHttpRequest`, `AlphaMath.api` or `AlphaMath.ids` anywhere in this
client's scripts. Work left the browser by exactly one route: `exportRecord()`
writing a `.txt` file to the learner's downloads. Everything else lived in
`localStorage` and stayed there.

So Phase 8 was not a translation between two protocols. It was **building the
submission path**, in the shape the existing server already accepts. The
direction was unchanged — the backend is not forked, branched or special-cased
for this syllabus — but the work was larger than "adapter" implies. Recording
that here because the discrepancy is in the hand-off, not in the code.

## The two shapes

This client stores an attempt as a **sparse object keyed by question position**;
the API wants a **dense array of self-identifying items**. That gap is the whole
adapter.

| This client | The evidence API | Note |
|---|---|---|
| `state.responses = {"3": {...}}` | `responses: [ …, …, …, {...} ]` | Sparse → dense. A learner who answers only Q4 has a one-key object; the record still needs every item. |
| *(position only)* | `itemId` | `question.label`, falling back to 1-based position — never the string `"0"`. |
| *(none)* | `answerSchemaVersion: 1` | Version 2 carries lettered parts (a)/(b)/(c). This instrument has one answer field per question, so 1 is the truthful claim. |
| *(none)* | `parts: {}` | Consistent with version 1. |
| `answer`, `flagged`, `drawing` | same names | Passed through. The drawing stays an inline data URL, as in Additional Mathematics. |
| *(none)* | `sketchpadSize: "standard"` | This pad is fixed-size and exposes no size control. |
| `state.submitted` | `locked` | **Passed through, never asserted.** The server rejects an unlocked attempt on purpose. |
| `state.startedAt` (ms, resets on resume) | `startedAt` (ISO, once) | New `state.firstStartedAt`. The old field is the current *run*, not the attempt. |

### Why `firstStartedAt` had to be added

`state.startedAt` is a millisecond timestamp that is reset every time the clock
resumes — on `startExam`, and again on every `visibilitychange` back into the
tab. It answers "when did this sitting resume", not "when did this attempt
begin". Sending it would have put a start time *after* some of the work on the
record. `firstStartedAt` is written once, in ISO, and never overwritten.

## Verified

Browser-driven attempt on the real page, then its actual payload POSTed to the
real server built on `MemoryRepository`:

- `POST /v1/exam-attempts` → **201**
- `GET /v1/tutor/exam-attempts` → the attempt is in the tutor queue, `count: 1`
- `GET /v1/exam-attempts/:id` → **200**, 20 responses, answers and flags intact

No server file was changed to make any of that work.

`node --test test/adapter-contract.test.mjs` → 8 pass. `node qa-suite.mjs` → pass.

## The duplication that will bite

`AlphaMath.api` and `AlphaMath.ids` in `assets/js/suite.js` are a **deliberate
port** of the same code in the Additional Mathematics client, not an independent
implementation. Two clients now speak the same protocol from two copies of the
transport, and they will drift on the first contract change.

That is a known cost, taken because the alternative — a shared module across two
separately-deliverable folders — introduces a build step neither client has.
**If you change one, change the other.** The contract test in each build is what
should catch you if you don't.

## Returned work (added 2026-07-31, after the adapter)

`marked-attempt.html` now exists in this build, so a CSEC Mathematics learner can
read their marked script. It is generated by `build-redesign.mjs` and gated on a
**learner session** — the shared deployment token cannot reach these routes.

`assets/js/auth.js` and `assets/js/marked-attempt.js` are ports of the Additional
Mathematics files, unchanged. Nothing in either is syllabus-specific; every value
is read from the evidence API. The `parts` branch in `renderItems()` is inert for
this syllabus (answer schema version 1 has no lettered parts) and falls through to
`item.answer` — kept rather than stripped so re-porting stays a copy, not a merge.

Verified end to end against the real server, with a genuinely marked attempt
(claim 200 → annotation 200 → review 201, all through the real routes):

- The learner signs in and sees only their own returned work
- The marked attempt renders: outcome, overall comment, per-item outcomes and comments
- **The two evidence layers stay two files.** Two separate `blob:` images with
  different SHA-256s, stacked at render time and never composited onto a canvas.
  Hiding the tutor layer reveals exactly what the learner submitted — measured as
  a `display` change on a distinct element, and confirmed visually (blue working
  under a translucent red overlay reads purple; hidden, it returns to pure blue).
- No console errors; no horizontal overflow at 375px; every control ≥44px

### The caption fix, and the port discipline working

The `<figcaption>` used to read "Your working, with your tutor's marks over it"
even after the learner hid the marks — a caption contradicting the image directly
above it, on the one page whose purpose is letting a learner tell their own work
from their tutor's. It was wrong in both builds, being a byte-for-byte port.

Fixed **upstream first, then re-ported** (2026-07-31), which exercised the whole
guard chain end to end:

1. Fixed in the Additional Mathematics build. The caption is now rewritten by
   `wireToggle()` for items carrying `data-has-marks`: "…with your tutor's marks
   over it" ⇄ "Your working, exactly as you submitted it". An item with no marks
   reads "Your working" in both states, because that is what it is.
2. `tools/qa-static.mjs` upstream gained a guard, verified to fire by baking the
   caption back in at render time.
3. **The pin in this build then failed**, exactly as designed — "Upstream
   marked-attempt.js changed (5e23658b0a81…). Re-port it and update the pin."
4. Re-ported by replacing everything from the IIFE onward and reapplying the port
   header, so the copy stays a copy rather than becoming a merge. Pin updated.
5. Verified in both clients: caption agrees with the image in both states, and
   the toggle is reversible.

This is the intended workflow for any future change to a ported file. Do not edit
the copy in this build directly.

## What Phase 8 does *not* include

Stated plainly so none of it is mistaken for done:

1. **Learner submission uses the shared deployment token**, not a per-user
   session — identical to the Additional Mathematics exam page. This is the open
   item already recorded in ADR 0002 ("the shared token is still accepted"); this
   adapter inherits it rather than introducing it. Retiring
   `ALPHAMATH_API_TOKEN` requires moving *both* clients' learner pages onto
   sessions.
2. **Tutor surfaces are not duplicated here.** The queue, claim, annotation and
   review pages are syllabus-agnostic and already serve both syllabuses from the
   Additional Mathematics build. Duplicating them would be the fork Phase 8 was
   written to avoid.
3. **Mastery logic was preserved by not touching it.** `mastery-config.json` is
   already identical across the two builds; the syllabus-specific part is the
   taxonomy (`csec-taxonomy.js`, M-codes), which the adapter never reads. Mastery
   remains a human tutor decision.

## The generator, and a defect this work found in its own Phase 8

Every HTML page in this build is written by `build-redesign.mjs`. **Phase 8
originally edited the built pages without updating the generator**, so the next
build would have silently reverted the Send control and the adapter's script tag
— the exam would still load, and submission would just be gone.

That is fixed. The generator now emits the Send control, the adapter script, the
nav entry and `marked-attempt.html`, and `qa-suite.mjs` carries two guards, both
verified to fire by deliberately breaking them:

- **Generator drift.** Anything the built HTML relies on must appear in
  `build-redesign.mjs`, and the built exam page and the generator must agree
  about the Send control.
- **Port drift.** The upstream `auth.js` and `marked-attempt.js` SHA-256s are
  pinned. An upstream change fails here with "re-port it and update the pin",
  rather than leaving two clients quietly disagreeing about the protocol.

`Students/…` **was** regenerated as part of this, contrary to the earlier note in
this document: those pages gained the nav entry, the Send control and the adapter.
Checked first that the HTML is pure template — a learner's answers and drawings
live in `localStorage`, not in the file — and backed up outside git beforehand,
since `.gitignore` means git could not restore it. The effect is that the pilot
learner can now actually submit and read returned work; leaving the files stale
would have excluded the one real student from the feature built for them.

## Intake descriptors and popovers (2026-07-31)

**The split.** A descriptor is what a learner reads while scanning 144 rows for
the point their confidence drops, so it is plain English with no notation. The
popover behind the (i) button is where notation lives: a standard formula, an
illustrated rule, or a worked calculation. It must not restate the descriptor or
merely cite the syllabus — the learner has read the descriptor, and a citation
gives them nothing to act on.

Authored in `assets/data/csec-intake-guides.js`, in the Additional Mathematics
convention exactly — `{"rows": [["Label", "LaTeX"]]}` rendered through
`formulaStatementLatex()` as `\text{Label},\;LaTeX` and typeset by KaTeX.

**Coverage went from 5 topics to 144.** Before this, five topics had a popover and
each showed only a syllabus line.

**34 descriptors were not merely notation-heavy — several were wrong**, having
lost their structure on the way into HTML:

| Rendered as | Should be |
|---|---|
| `V=43π r3` | 4⁄3 π r³ |
| `θ360× circumference` | θ⁄360 × circumference |
| `sinθ=OH, cosθ=AH` | opposite⁄hypotenuse, adjacent⁄hypotenuse |
| `T=2π√lg` | 2π√(l⁄g) |
| `y∝1x ⇒ y=kx` | y ∝ 1⁄x ⇒ y = k⁄x — the inverse law was identical to the direct one |

That last one, `M2.2.8`, taught the wrong mathematics.

**Sketchpad button position.** It sat inline beside the answer field; the
reference build puts it on its own row *below*, with a line of guidance. Matched.

Four guards added, each verified to fire: descriptors carry no notation, every
topic has a guide, no guide references a code outside the taxonomy, and no guide
is prose-only.

## Suite-wide parity and the CSEC Mathematics ink (2026-07-31)

### The palette, and why the suite looked like two documents

`assets/css/palette.css` is now the single source of truth for this build's purple
family, read by both `alphamath.css` and the intake form. Before it existed,
`alphamath.css` sat on Marion Sydney Classic `#552583` while the intake carried
`#140B2C` under its own `--wisteria`/`--amethyst` vocabulary **and declared its
tokens twice at different values** — so the suite genuinely rendered as two
documents. That is the same failure the Additional Mathematics build had already
fixed; this one had never received the fix.

CSEC Mathematics takes `#221A2D` (§9 Royal Purple Gradient Palette #1, column 1
step 10) — CEO decision 2026-07-31, on the reasoning that the two syllabuses are
different subjects and should be visually distinct. Every token is a step of that
one ramp, so the family is a single coherent gradient rather than an assembly.

    CSEC Maths   #221A2D   16.75 : 1 on white
    Add Maths    #140B2C   18.85 : 1 on white   (CDR-0146)
    CIEDE2000 separation 6.56 — clearly distinct, not a near-duplicate.

Contrast measured at every role, because this is material for minors: chrome
16.75, hero 6.96, borders 3.18 (clears 1.4.11's 3:1), fills 8.19 against ink.

**Open with the CEO:** `#221A2D` appears in the register only as a ramp-table
cell. If it is to be named document chrome it needs a §2 entry under a CDR, as
`#140B2C` has. Separately, `--gold-deep:#795d16` is in **neither** build's
register — zero occurrences — and is used as text on a light surface, which §5's
identity rule bans regardless of hex.

### The wholesale parity check

`qa-suite.mjs` now diffs the two builds' **full** CSS selector sets — 309
reference selectors — and fails on any divergence not declared in
`ALLOWED_DIVERGENCE` with a reason. The burden is on divergence to justify itself,
which is the opposite of how this drifted.

It earned its keep immediately: on first run it found ten divergences that three
rounds of manual inspection had missed. Nine were legitimate (palette-derived
tints, reference-build-only content) and one was real — a missing `width:100%`.

**It also caught a live bug.** An earlier partial port had copied the
`@media(max-width:620px)` review rules **without their media query**, so the
stacked mobile layout was applying at every width and the review panel never
rendered as a table. Now verified in both directions: `table` at 901px, `block` at
375px.

### Sketchpad sizes

Ported from the reference build. Three sizes, and the size the learner chose now
reaches the server: the adapter previously hardcoded `"standard"` with a comment
asserting the pad had none. That mattered more than it looks — the annotation
route rejects a tutor overlay whose pixel dimensions do not match the pad, so an
expanded pad reported as standard would have been un-markable, and the failure
would only have surfaced when a tutor tried to mark it.

### `drafts.js` is correctly absent

Recorded because the audit first flagged it as missing. It is consumed only by
`tutor-review.html`/`tutor-review.js` — tutor surfaces this build deliberately does
not duplicate. Porting it would add 116 lines of dead code.

## Simulated-exam parity (2026-07-31)

Four defects, all of them gaps against the Additional Mathematics build rather
than new breakage:

| | Was | Now |
|---|---|---|
| Question navigator | `repeat(5,1fr)` in a 220px sidebar — needed 244px in a 174px box, so the buttons spilled over the Previous/Flag/Next row | `repeat(auto-fit,minmax(44px,1fr))` + `overflow:clip`, 280px sidebar |
| Sketchpad | "Draw working", and "Drawing area for…" as the accessible name | "Sketchpad" in both |
| Per-question pace | nothing — the whole-exam countdown was the only timing signal | dial per question, banked across navigation and reloads |
| Tutor review | no `review.js` in this build at all | ported and mounted via `data-review-kind="exam"` |

Two things worth knowing:

- **The recommended per-question time is derived, not copied.** Additional
  Mathematics falls back to a flat 300s. On this 45-minute, 20-question paper that
  would mark every question as comfortably under pace — worse than showing
  nothing — so it derives `durationSeconds / questions.length` (135s, shown as
  "Recommended 2:15"). A per-question `recommendedSeconds` in the content data
  still wins. `exam.js` is **not** a hash-pinned ported file; the two builds
  maintain it separately, so this divergence is legitimate.
- **A missing Phase 7 fix surfaced.** The review panel's `<select>` measured 23px
  against the 44px floor, because the global control rule from the Additional
  Mathematics build's Phase 7 hardening had never been ported here. It is now, and
  the navigator buttons went from 42px to 44px — two pixels short is close enough
  to look right and still fail.

Verified in-browser at 1280px, 900px and 375px: no page, navigator or sidebar
overflow at any width; zero controls under 44px; no console errors. Per-question
timing was checked behaviourally, not just rendered — Q1 banked 13s while Q2
banked 2s, and returning to Q1 resumed at 13s rather than resetting.

**Guard limitation, stated plainly.** The QA guards catch *removal* — deleted
markup, a deleted call, a hardcoded recommendation. They cannot catch a partial
rename (function renamed, call site not), because the substring still matches.
That failure mode throws immediately in the browser rather than degrading
quietly, so it is caught by running the page, not by static text matching.

### Running the generator safely

`build-redesign.mjs` used to be the one genuinely destructive thing here: it wrote
into `Students/`, which is gitignored, so a careless run destroyed real learner
work that git could not restore. It is now safe by default.

```bash
node build-redesign.mjs                     # regenerate; Students/ is skipped
node build-redesign.mjs --students          # include Students/, backed up first
node build-redesign.mjs --target /tmp/probe # build elsewhere; this folder untouched
```

- **Default skips `Students/`** and says so, listing what it declined to write —
  loudly, because a build that silently left pages stale is how the generator and
  its output drift apart in the first place.
- **`--students`** backs up each file it is about to overwrite into
  `Students/_backups/<timestamp>/`. That location is deliberate: it sits *inside*
  `Students/`, so it inherits the existing ignore. A first attempt used a sibling
  `Students.backup-<stamp>/`, which `**/Students/` does **not** match — leaving a
  copy of a learner's work fully committable. `qa-suite.mjs` now fails if the
  backup path moves back outside.
- **`--target`** makes the scratch-build workflow supported rather than a hack;
  authoring sources still resolve against the canonical folder, so asset copies
  work. Writing to a scratch target cannot clobber a learner file, so `--students`
  is implied there.

Every write and copy passes through a single `guard()`, so a `write("Students/…")`
added later is covered without anyone having to remember. Six guards in
`qa-suite.mjs` protect all of this, each verified to fire by deliberately breaking
what it guards.
